## 1. 完成の定義（R1）

**Web システムとして起動し、画面で GitHub の URL／GitHub から取得した .zip／ソースコード（フォルダ・ファイル）を渡すと、仕様書と設計書を生成し、画面で閲覧・4 形式（Markdown / Word / HTML / Excel）でダウンロードできる。**

| 区分 | 文書 |
|---|---|
| 仕様書 | D01 概要書／D02 要求仕様書／D03 画面仕様書／D04 データ仕様書／D05 データ連携仕様書 |
| 設計書 | D11 基本設計書（方式・アーキテクチャ・モジュール構成・外部 I/F）／D12 詳細設計書（モジュール・関数の入出力・処理フロー・シーケンス・例外） |
| 移行向け | D06 依存ライブラリ一覧／D07 移行論点・技術的負債一覧 |
| 検証用 | D08 解析カバレッジ・追跡レポート（記述 → ソース位置）／D09 確認事項一覧（ソースから確定できない点） |

- 水準: テスト設計コンテスト Open クラス題材（だんだん動物園・話題沸騰ポット）と同等。ID 付きの相互参照・数値と単位の明記・状態と遷移・エラー一覧
- R1 の対象言語: JavaScript / TypeScript / HTML / CSS。R2 で Java・C#/VB.NET・Python・PHP・SQL、R3 で COBOL・JCL
- 合格: 受入テスト（7 観点の再現率 90% 以上）を保守者が判定する

## 7. リスク

| リスク | 影響 | 対応 |
|---|---|---|
| ソースから復元できない要素（業務背景・数値の理由） | 再現率が 90% に届かない | D09 に回して事実として書かない。再現率の分母を M2 で確定 |
| LLM の推測が事実として混ざる | 仕様書・設計書の信頼性が落ちる | D08 で記述ごとにソース位置を追跡し、推測に印を付ける |
| .zip 経由の攻撃（zip slip・展開爆弾） | 端末のファイル破壊・停止 | U1 で上限と展開先の固定。M4 で異常系テスト |
| Word / Excel の書式崩れ | 納品物として使えない | U7 で見本 1 つを決めて検証 |
