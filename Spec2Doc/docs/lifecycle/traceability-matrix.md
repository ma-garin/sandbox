> 要件と下流成果物の対応は**この表だけ**が真実源。工程文書側に対応表を複製しない。
> 検証は目視でなく `./scripts/trace-check.sh [対象ディレクトリ]` で行う。
> ID 体系と検査内容は `skills/dev-lifecycle/references/traceability.md`。

**最終更新**: 2026-09-25（工程 1 要件定義まで。BD 以降の列は工程 2 以降で割り当てるため「未割当」）

## 記入規則

- 1セルに複数 ID を書く場合はカンマ区切りで併記する
- 該当しないセルは `-` を入れる。**空欄はカバー漏れとして検出される**
- `REQ-F` は **UAT 列必須**、`REQ-N` は **ST 列必須**（V字の対応）
- 状態: `未着手 / 実装中 / 検証中 / 合格 / 保留`
- 「未割当」は下流工程が未着手であることを示す。trace-check.sh はこれをカバー漏れ（NG）として数える。工程 2・7・8 の出口で 0 にする
