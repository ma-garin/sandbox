## このプロジェクトの概要

社内文書をAIエージェントに渡す前に「そのまま変換していいか」を判定し、
AIに添える構造説明文と、エージェントが最初に読む索引（目次）を生成するツール。

前提となる問題意識は「ExcelやPDFを .md に変換すればAIが読みやすくなる」という
通説が実証研究では支持されないこと。特に結合セル・多階層ヘッダはMarkdown記法で
表現できず、変換した時点で構造情報が消える。
このツールは最適化ではなく、情報が消える変換を避けるための足切りとして設計されている。

## 使用技術・制約

- 単一HTML / 外部依存は Google Fonts のみ / ビルド不要
- GitHub Pages で即公開できる状態を維持する

### 変更してはいけない前提

1. **単一HTML・依存なし・ビルド不要を維持する。** フレームワーク（React/Vue 等）を導入しない
2. **ブラウザストレージ（localStorage 等）は使わない。** 永続化は JSON の手動保存・読込で代替する
3. **判定ルールを増やすときは必ず出典を伴わせる。** 根拠のないルールは入れない。
   「根拠」タブの出典表に必ず追記する
4. **デザイン**: Material Design 3 ライトテーマ / primary `#1976D2` /
   背景 `#F8F9FA`・`#FFFFFF` / Noto Sans JP + JetBrains Mono。
   既存の CSS 変数定義を踏襲する
5. **UI文言**: 日本語は非エンジニアが読める語彙に保つ。
   「トークン」「チャンク」「シリアライズ」等は UI 文言に出さない（「根拠」タブ内は専門用語可）

### スコープ外

- サーバーサイド実装、DB、認証
- 実際のファイル変換処理（本ツールは判定と索引生成のみ。変換は別工程）
- AI API 呼び出し（ゼロ予算制約のため）
- フレームワーク導入（React/Vue 等）

## 作業の進め方

- タスク1つごとにコミットを分ける。コミットメッセージは日本語で、何を変えたかを一行で
- リファクタ時は、既存の判定結果が変わっていないことを
  サンプル入力（「サンプルを入れる」ボタンの内容）で確認してから次に進む
- 判断に迷う箇所は実装前に確認を取る。特に判定ルールの追加・変更は勝手に行わない
