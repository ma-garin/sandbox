ソースコードからの仕様書づくり

GitHub・.zip・フォルダのソースを解析して、概要書からテスト観点表までの文書と、文書の行とソースの対応（トレーサビリティ）を作ります。

  1. ソースを渡すGitHub の URL・.zip・フォルダのパス
  2. 仕様書を生成文書と出力形式を選んで作る
  3. トレーサビリティで確かめる文書の行とソースの対応を確認

所要時間の目安: デモ 19 ファイルで約 2 秒

入力

ブランチ等が空欄なら既定のブランチを使います。非公開リポジトリはサーバの環境変数 GITHUB_TOKEN にトークンを設定して起動します。

読み取り専用の一時領域に展開して解析し、終わったら消します。

このサーバを動かしている端末のフォルダを絶対パスで指定します。

設定

出力形式

LLM

ソースの一部を外部の LLM に送ります。キーはサーバの環境変数 ANTHROPIC_API_KEY から読みます。

除外パターン

1 行に 1 つ、glob で書きます。空欄なら既定の除外（node_modules・.gitignore など）だけを使います。

実行の内容

目安はデモ 19 ファイルでの所要時間です。ファイルが多いほど、LLM を使うほど長くなります。

実行の詳細

使う流れ

  1. ソースを渡す「文書の作成」で GitHub の URL・.zip ファイル・フォルダのパスのどれかを入れます。
  2. 仕様書を生成文書の種類と出力形式を選び、「文書を作る」を押します。デモ 19 ファイルで約 2 秒です。
  3. トレーサビリティで確かめる文書の行とソースの対応を 1 件ずつ確かめ、未確認を減らします。

入力・設定・処理時間・ファイル件数・LLM の使用量は「実行記録」に残ります。

出力される文書

文書区分内容

根拠ラベル

文書の各記述には、ソースからどう読み取ったかを示すラベルが付きます。

事実
ソースの記述からそのまま読み取れた内容です。
推測
名前や構造から推し量った内容です。使う前に人が確かめてください。
不明
ソースから確定できなかった事項です。D09 確認事項一覧にまとまっています。

コマンドで使う

同じ処理をコマンドでも実行できます。使い方は node src/cli.ts --help で表示します。

node src/cli.ts --folder ./my-app --docs D01,D03 --format md,html
